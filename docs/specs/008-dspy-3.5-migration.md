# Spec 008 - DSPy 3.5.0 migration

Status: implemented; full-suite integration validation owned by the workstream.

## Problem

Fleet Agent pins DSPy in `apps/api/pyproject.toml`. Bumping the pin to `3.5.0`
without changing code broke 9 tests, because 3.5.0 renames the ReAct loop and
changes one error message that the engine parses.

## Measured baseline

| Configuration | Result |
| --- | --- |
| DSPy 3.4.0 | 560 passed, 1 skipped (112s) |
| DSPy 3.5.0, no code changes | 9 failed, 551 passed, 1 skipped (67s) |

Three root causes:

1. **Forced-submit message prefix.** `_FORCED_SUBMIT_REASON_RE` matched
   `"ReActV2 failed to produce final outputs after ..."`. DSPy 3.5 raises
   `"ReAct failed to produce final outputs after {reason}: ..."`, so
   `_reason_from_react_exc` returned `None` and runs surfaced `internal_error`
   instead of `agent_no_output` / `agent_parse_error`.
2. **Removed legacy LM API.** `BaseLM.forward()` and `lm(messages=[...])` with
   OpenAI dicts are gone; `__call__` takes `lm15.Request | str`. Three test
   files still overrode `__call__(prompt=None, messages=None, ...)`.
3. **`Tool.format_as_litellm_function_call()` removed.** Replaced by
   `Tool.as_function_tool()`, which returns an `lm15.FunctionTool` model.

## Current behavior

`app/agent/signature.py` builds the evidence loop with `dspy.ReActV2`, which
3.5.0 keeps only as a deprecated shim over `dspy.ReAct` and removes in 3.6.0.
`app/agent/engine.py` extracts the termination reason with a regex anchored on
the class name `ReActV2`, and version-qualified wording ("DSPy 3.4.0 ReActV2")
explains synchronous tool execution in several modules.

## Desired behavior

Name the loop `dspy.ReAct` everywhere in production code, comments, docstrings,
the README and specs. Extract the forced-submit reason from the stable part of
the message only, so a future rename cannot silently break public error
mapping. Keep every public symbol, seam and guard unchanged.

## Contract decisions

- **D1** - the loop is `dspy.ReAct`. `ReActV2` is removed from code, comments,
  docstrings, specs and README.
- **D2** - reason extraction is class-name independent:
  `re.compile(r"failed to produce final outputs after (?P<reason>\w+):")`.
  `_REASON_TO_PUBLIC_CODE` and the `_map_react_raise` seam are unchanged.
- **D3** - keep the async-tool guard. `ReAct` still runs tools synchronously
  inside `forward`; the message now says DSPy 3.5 / ReAct.
- **D4** - do not strip DSPy's per-turn `turn_budget` history key. It is
  server-side only and must not reach AG-UI events, public answer fields or
  `evidence_json`.
- **D5** - no LM API rewrite in production code. Only test LM interception
  moves to `Request`.
- **D6** - no new dependency, abstraction or extension point. Delete stale
  wording.

## Verified DSPy 3.5 semantics

Checked against the installed wheel (`dspy/predict/react.py`) and with inline
probes against the project venv:

- `ReAct.forward` passes the passed `dspy.History` through `_coerce_history`,
  which returns the same object for a `dspy.History` argument, and
  `_append_history_event` mutates `history.messages` in place. The returned
  `Prediction.history` is that same object. Probe: identical `id()`, identical
  `Prediction.history is history`, message count grew. `engine._capture_history`
  therefore still sees the partial history of a failed run.
- `_execute_tool_calls` calls `self.tools[name](**args)` inside `forward`; the
  `await ....acall(...)` path exists only in `aforward`. An async tool therefore
  returns a coroutine that is never awaited (DSPy converts the failure into an
  error observation), which is why the guard rejecting async tools is still
  correct.
- Each turn adds `turn_budget` to its history event, including the forced final
  submit, so a replayed history event reproduces the request prefix.
- `dspy.ReActV2` is a `class ReActV2(ReAct)` deprecation shim.

## Invariants

- Public `termination_reason` and `error_code` values are unchanged and
  independent of the DSPy class name.
- Unauthorized tools are still withheld before the program is constructed.
- Raw `dspy.History`, including `turn_budget` and `next_thought`, never reaches
  AG-UI events, public answer fields or `evidence_json`.
- Streaming output equals the settled safe final fields.
- No behavior, setting, dependency or public symbol is added or renamed.

## Public contract impact

None. No event, field or schema version changes. The `turn_budget` key stays in
persisted `dspy_histories.history_json` only; `AgentRunResult.history` remains
server-side and is not serialized to the browser.

## Frontend impact

None.

## DSPy and evaluation impact

The DSPy dependency footprint shrank: `uv sync` removed `tiktoken`,
`tokenizers`, `tenacity`, `truststore` and `sniffio` from the resolved
lockfile. No agent-quality change is claimed; the migration is behavior
preserving and no eval was re-measured for it.

## Tests

The 9 failing tests are addressed by D1-D3 and by migrating test LM overrides
to `lm15.Request` and `Tool.as_function_tool()`. Full-suite execution is
performed by the workstream integration step, not by this change.

## Acceptance criteria

- `import dspy` reports `3.5.0`; `build_gatherer` returns `dspy.ReAct`.
- A `"ReAct failed to produce final outputs after max_iters: ..."` raise maps to
  `agent_no_output`; `parse_error` maps to `agent_parse_error`;
  `context_window_exceeded` maps to `agent_context_limit`.
- No `ReActV2` or version-qualified `DSPy 3.4` wording remains under
  `apps/api/app/` or in `README.md`.
- `ruff check` and `mypy` pass on the changed modules.
- Full suite green in DSPy 3.5.0 at workstream integration.

## Non-goals

No LM-layer rewrite, no new abstractions, no dependency beyond the pin bump,
no frontend change, no removal of `turn_budget` from persisted history.
